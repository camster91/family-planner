# Transactional Email Provider Decision

**Date:** 2026-09-01  
**Status:** Recommendation prepared; external configuration and test sends await
release-owner approval.

## Recommendation

Use **Resend Free** for the five-household design-partner beta. Keep Maton as a
documented fallback, but do not configure both providers at the same time.

Resend is the better fit because it is purpose-built for transactional email,
the application already has a tested direct integration, and its free plan
includes 3,000 messages per month with a 100-message daily limit. That capacity
is sufficient for the beta under the conservative planning assumption of no
more than ten verification or recovery messages per household per day.

## Proposed beta configuration

These values are proposals, not authorization to change external systems:

| Setting                 | Proposed value                                      |
| ----------------------- | --------------------------------------------------- |
| Provider                | Resend Free                                         |
| Sending subdomain       | `mail.family.ashbi.ca`                              |
| Sender                  | `Family Planner <noreply@mail.family.ashbi.ca>`     |
| Runtime credential      | `RESEND_API_KEY`                                    |
| Sender variable         | `EMAIL_FROM`                                        |
| Credential permission   | Sending access restricted to `mail.family.ashbi.ca` |
| Review application host | `family-review.ashbi.ca`                            |

The release owner should copy the exact SPF and DKIM records generated by the
provider; this repository must not guess or store them. A sending subdomain
isolates reputation from other `ashbi.ca` services. Add DMARC deliberately
after checking the parent domain's existing policy.

## Guardrails

- Never commit or print the API key.
- Configure review and production separately.
- Do not add a Maton credential when Resend is active.
- Keep onboarding paused when provider health is degraded or a test message
  bounces, fails, or does not arrive.
- The free plan's 100-message daily limit is a beta ceiling, not a reason to
  silently upgrade. Any paid-plan change requires a new cost decision.
- Review the provider's data-processing terms before inviting real households;
  verification and recovery messages contain personal email addresses and
  time-limited links.

## Exact approval package

Before configuration, obtain explicit approval for all of the following:

1. Create or use a Resend account on the free plan.
2. Add Resend's generated DNS records for `mail.family.ashbi.ca`.
3. Create a sending-only, domain-restricted key and store it in the Ashbi review
   runtime secret store as `RESEND_API_KEY`.
4. Set `EMAIL_FROM` to the proposed sender and restart the exact review image.
5. Use an explicitly approved owner-controlled inbox for one verification and
   one password-recovery acceptance test.

After approval, execute the
[transactional email release runbook](TRANSACTIONAL_EMAIL_RUNBOOK.md). Passing
review acceptance does not authorize production configuration or deployment.
